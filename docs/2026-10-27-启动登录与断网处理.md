# 启动登录与断网处理

## 行为

登录页面本身可以离线展示；加载图形验证码和提交登录需要连接后端。

| 场景 | 处理 |
| --- | --- |
| 清理后台后重新启动，没有登录记录 | 直接显示登录页，不发起自动登录验证 |
| 清理后台后重新启动，有登录记录且验证成功 | 恢复登录及聊天缓存，进入主界面并连接 WS |
| 清理后台后重新启动，断网或后端不可访问 | 清除登录凭据，显示登录页并提示联网后重新登录 |
| 启动验证一直没有返回 | 5 秒后取消验证请求并返回登录页 |
| 使用过程中断网，或进程仍在时离线切回前台 | 保留登录状态及主界面，继续原有重连机制 |

断网退出登录不会清空聊天缓存。后端明确返回登录凭据失效时，仍沿用原有退出登录流程。

## 实现

- `AppState.initialize` 仅在冷启动恢复时执行联网验证，验证成功后才设置当前用户及恢复缓存，避免先进入已登录状态。网络验证失败时清除登录凭据。
- 验证使用独立的 5 秒计时器和 Dio `CancelToken`。到期取消真实请求，避免只结束界面等待而让旧响应继续写回 Token。
- `ApiClient.refresh` 支持可选的取消令牌，使用中的鉴权刷新与 WS 重连不设置这个冷启动时限。
